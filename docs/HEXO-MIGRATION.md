# 기존 Hexo 글 복구

`GitHubBlog`의 생성된 HTML에서 글을 복구했습니다. 원본 폴더는 읽기만 했으며 기존 블로그의 파일과 배포 상태는 변경하지 않았습니다.

## 복구 결과

| 항목 | 결과 |
| --- | --- |
| 게시글 | 16개 |
| 기존 게시 날짜 | 2025-01-03, 2025-01-04, 2025-01-06 |
| 이미지 파일 | 12개 |
| 추가 아이콘 자산 | favicon.ico, iconfont.svg 2개 |
| 본문 로컬 이미지 참조 | 16개 |
| 코드블록 | 107개 |
| Plotly용 정적 iframe 페이지 | 1개 |
| 이전 URL → 새 URL 대응 | 16개 |

- 원고: `src/content/posts/legacy-*.md`
- 이미지·아이콘: `public/legacy-assets/` 아래 원래 폴더 구조
- Plotly iframe 페이지: `public/legacy-assets/embeds/legacy-plotly-01-1.html`
- URL 대응표: `src/data/legacy-routes.json`
- 복구 스크립트: `scripts/import-hexo.mjs`

## 실행

프로젝트 루트에서 실행합니다. 기본 입력은 이 사이트와 같은 상위 폴더에 있는 `GitHubBlog`입니다.

```sh
npm run import:hexo
```

다른 위치의 배포본을 읽을 때는 경로를 명시합니다.

```sh
node scripts/import-hexo.mjs "C:/Users/KE050/Desktop/GitHubBlog"
```

`cheerio`, `turndown`, `github-slugger`를 사용합니다. 날짜별 `YYYY/MM/DD/글/index.html` 중 `.post-content`가 있는 실제 게시글만 가져오며, 아카이브·목록·페이지 이동 화면은 글로 추가하지 않습니다.

## 보존 기준

아래는 최초 복구 당시의 기준이다. 2026-10-15에는 요청에 따라 6편을 개정하고 수정일을 추가했다. 대상과 검증 범위는 [게시글 개정 기록](./CONTENT-REVISION.md)을 참고한다. 나머지 원고는 최초 복구 상태를 유지한다.

제목·카테고리·태그는 렌더링된 게시글 메타데이터에서 읽습니다. 날짜는 기존 URL의 연·월·일을 그대로 사용하여 운영체제 시간대에 따른 날짜 이동을 피했습니다. 첫 문단을 소개 문구로 사용했으며 원문 설명과 코드의 내용을 새로 집필하거나 최신 사용법으로 수정하지 않았습니다.

본문에서는 Hexo의 줄번호·구문강조용 표를 언어 정보가 있는 Markdown 코드블록으로 복구했습니다. 중복된 본문 제목은 제거하고 기존 제목 앵커는 보존했습니다. 기존 목차 링크를 위해 Hexo의 heading ID를 보존하되 Astro의 자동 ID와 같을 때는 별도 앵커를 추가하지 않습니다. 기존 목록·표·인라인 코드·외부 링크는 유지합니다.

본문에 남아 있는 최상위 제목은 사이트의 글 제목과 겹치지 않도록 하위 제목으로 한 단계 내립니다. 하위 절의 상대적인 단계와 기존 앵커는 유지합니다.

내부 글 링크는 새 `/writing/legacy-.../` 주소로 바꿉니다. 로컬 이미지 경로는 `/legacy-assets/...`로 통일했습니다. 루트보다 위로 올라가는 형태의 기존 이미지 주소 `/../images/...`도 정상 이미지 경로로 해석합니다.

URL 대응표의 `from`은 실제 기존 링크처럼 공백을 `%20`으로 표현합니다. 예를 들어 `/2025/01/03/plotly%20graph/`는 `/writing/legacy-plotly-graph/`에 대응합니다. 파일 경로를 생성하는 코드는 `decodeURI(from)`를 사용해야 합니다. 브라우저 이동 시 기존 URL의 해시도 전달하면 복구한 목차 앵커를 활용할 수 있습니다.

## 원본에서 확인된 보정 3건

1. `plotly_01` 글은 원본 제목이 비어 있어 기존 경로 이름을 제목으로 사용했습니다. 작성자 임의의 새로운 글 제목을 붙이지 않았습니다.
2. 오라클 설치 글의 `!(../images/install_01.png)`는 원본에서도 이미지가 아닌 일반 문자열로 표시되던 잘못된 문법입니다. 실제 이미지 파일이 있어 정상 Markdown 이미지로 복구했습니다.
3. Plotly 설명 글에 있는 `src="your_url"` iframe은 실행 가능한 주소가 없는 예제입니다. 깨진 프레임 대신 기존 iframe 태그를 HTML 코드블록으로 보여줍니다.

## Plotly의 외부 의존성

`plotly_01`의 실제 그래프는 원본부터 `https://plotly.com/~letsplay2ya/1.embed`를 불러옵니다. 새 사이트에는 이를 담는 정적 HTML을 복사해 분리했고, 원고에서는 그 로컬 페이지를 iframe으로 표시합니다. 글 본문에 실행 스크립트를 추가하지 않았습니다. iframe 페이지에는 원본 그래프를 별도 창으로 여는 링크도 있습니다.

기존 배포본에는 그래프 데이터와 Plotly 런타임이 포함되어 있지 않습니다. 인터넷 연결과 원본 Plotly 공개 상태가 필요하며 오프라인으로 그래프를 재현한 것은 아닙니다.

## 재실행과 수동 편집

생성 원고에는 `hexo-import:v1` 체크섬 주석이 들어갑니다. 재실행 시 이 주석이 있고 이전 생성 내용과 일치하는 글만 갱신합니다. 생성 후 사람이 수정한 글은 건너뛰고 로그에 남깁니다. 동일 이름의 수동 원고가 있으면 덮어쓰기 전에 중단합니다. `legacy-` 이외의 글과 원본에서 사라진 글은 삭제하지 않습니다.

복사한 자산과 iframe 페이지가 원본 또는 생성 결과와 달라졌다면 덮어쓰지 않고 중단합니다. `legacy-routes.json`은 복구 스크립트가 관리하는 생성 파일이므로 수동 수정 내용은 재실행으로 바뀔 수 있습니다. 직접 작성한 글은 `legacy-` 이름을 사용하지 않고 별도 파일로 관리하면 됩니다.

같은 배포본으로 재실행했을 때 16개 원고의 체크섬이 모두 같음을 확인했습니다. HTML 복구는 원본 Markdown의 공백·목록 표기·front matter 전체·초안·수정 이력을 되살리는 작업은 아닙니다. Hexo 원본 설정과 원고가 발견되면 이 복구본과 비교할 수 있습니다.
