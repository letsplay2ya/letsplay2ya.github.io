# 기술 글 계획: 분야별 28개 주제와 진행 상태

2026-10-16 기준. 28개 주제 중 약관 판정과 스크롤 동기화 2편을 발행했고, 나머지 26개는 작성 후보다. 후보는 완성된 글 수에 포함하지 않는다. 프로젝트 소스가 있다는 사실만으로 작성자의 기여나 운영 효과를 확정하지 않는다.

현재 공개 글은 일반 목록 24편, 보관함 3편이다. 글 수보다 더 큰 편중은 React 업무 사례에 비해 Java·Vue·전환 경험의 구체적 사례가 적다는 점이다. 같은 React 문제를 잘게 나누는 방식으로 수를 늘리기보다, 다음 프로젝트 자료에서 다른 분야의 사례를 확보한다.

표의 상태:

- **현재 자료**: 코리안리 프론트 소스나 공개 예제로 시작 가능. 재현·검증은 작성 과정에서 추가.
- **추가 프로젝트**: 실제 Java/Vue/전환 프로젝트와 본인 기여 확인이 먼저 필요.
- **별도 실험**: 운영 경험으로 표현하지 않고 작은 실행 예제로 작성 가능.

## 이번에 발행한 글

- [약관을 적용했는데 왜 할인할증 목록에는 없을까](https://letsplay2ya.github.io/writing/notes-clause-eligibility/) — 조건표, 누락 정책, 파생 행 갱신의 경계, 판정 예제.
- [너비와 순서가 다른 두 그리드의 스크롤을 맞추려면](https://letsplay2ya.github.io/writing/notes-keyed-scroll-sync/) — 원본 훅을 실행하는 키·비율·DOM 교체 예제.

| 후보 제목과 핵심 질문 | 필요한 내용·증거 | 상태 |

| --- | --- | --- |

모델 호출 성공만으로 실용성을 주장하지 않는다. 현재 6개 인공 사례는 개발용 예제이며 일반 성능 벤치마크가 아니다. 별도 평가 세트와 비교 기준을 마련한 뒤 수치를 공개한다.

## 글 하나를 공개하기 전 확인할 기준

1. 제목의 질문을 실제 입력·행동·실패 결과로 재현한다.
2. 관련 소스의 어느 부분이 결론을 뒷받침하는지 보여 준다.
3. 대안 하나 이상과 비용을 비교한다. 당시 의사결정과 지금의 분석을 구분한다.
4. 성공 예제뿐 아니라 실패·경계 조건을 실행한다.
5. 실제 업무, 별도 실험, 아직 확인하지 못한 결과를 구분한다.
6. 길이는 주제에 맞춘다. 같은 주장을 늘여 쓰거나 도구 설치 순서로 분량을 채우지 않는다.

6편씩 두 묶음을 작성하고, 공개 글 36편을 채우는 것보다 Java·Vue·전환의 근거가 충분히 생겼는지를 점검한다. 출처와 재현이 없는 분야는 글 수로 보완할 수 없다.
