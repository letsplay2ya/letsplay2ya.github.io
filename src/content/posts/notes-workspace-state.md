계약 화면에서 저장해야 할 상태는 입력값만이 아닙니다. 선택한 하위 탭, 비교 중인 참고 계약, 여러 담보와 요율 화면의 편집 내용도 사용자가 돌아왔을 때 이어져야 합니다. [코리안리 특종보험 프로젝트](/projects/koreanre-ai-assistant/)에서는 이 상태를 계약 번호별 스냅샷으로 관리했습니다.

## 화면의 경계와 업무의 경계

계약 기본정보·약관·상세정보·요율은 서로 다른 컴포넌트와 Zustand store에 나뉘어 있습니다. 그러나 사용자는 이 화면들을 하나의 계약 업무로 인식합니다. 다른 계약을 열었다고 해서 이전 계약의 편집값이 사라지거나 새 계약에 섞이면 안 됩니다.

저장·복원의 기준을 컴포넌트 하나가 아니라 UW 번호로 정했습니다. 스냅샷에는 여러 store의 데이터와 선택한 메인·하위 탭, Assistant 표시 상태를 함께 담습니다. store에서 동작을 수행하는 함수는 제외하고 복원할 데이터만 수집합니다.

## 이탈할 때 저장하고, 복원한 뒤 표시하기

업무 전환으로 기존 화면이 해제될 때 현재 스냅샷을 보관합니다. 이때 오래된 클로저가 마지막 편집값을 읽지 않도록 ref에 최신 캡처 함수를 유지합니다.

다시 진입한 화면은 해당 계약의 스냅샷을 각 store에 복원한 뒤 탭 콘텐츠를 표시합니다. 이렇게 해야 복원이 끝나기 전의 다른 계약 데이터로 무거운 하위 화면이 먼저 초기화되는 상황을 피할 수 있습니다.

흐름은 다음과 같습니다.

1. 계약 A의 입력값과 탭 상태를 편집합니다.
2. 다른 계약으로 이동할 때 A의 스냅샷을 보관합니다.
3. 계약 B의 상태로 작업합니다.
4. A에 다시 진입하면 A의 스냅샷을 복원합니다.
5. 저장소 복원을 마친 뒤 A의 탭 콘텐츠를 표시합니다.

다음은 개념을 설명하기 위해 새로 작성한 축약 예시입니다. 실제 코드는 여러 store의 데이터와 화면 생명주기를 함께 다룹니다.

```ts
type WorkspaceState = {
  activeTab: string;
  fields: Record<string, string>;
};

const snapshots = new Map<string, WorkspaceState>();

function leave(id: string, state: WorkspaceState) {
  snapshots.set(id, structuredClone(state));
}

function enter(id: string) {
  const snapshot = snapshots.get(id);
  return snapshot ? structuredClone(snapshot) : null;
}
```

## 원본과 편집 상태 구분하기

현재 편집 상태와 서버와 동기화된 기준 상태는 목적이 다릅니다. 편집 중인 스냅샷과 별도로 원본 스냅샷을 깊은 복사해 보관하고, 초기화할 때 그 원본을 사용합니다. 중첩 객체의 참조를 공유해 편집과 함께 원본까지 바뀌는 상황을 방지하기 위한 구성입니다.

종목별 저장소에는 추가 복원 규칙이 있습니다. 임원배상 요율 상태는 소유 계약을 확인하며 복원하고, 스냅샷에 해당 상태가 없으면 정해진 초기 상태로 준비합니다. 스냅샷은 여러 객체를 모으는 작업과 함께 각 데이터의 소유 계약을 지키는 작업이기도 합니다.

## 확인할 동작

- A를 편집한 뒤 B로 이동하고 A로 돌아왔을 때 값과 탭 위치가 이어지는지 확인합니다.
- 화면에서 마지막으로 바꾼 값이 이탈 시 스냅샷에 포함되는지 확인합니다.
- 중첩 값을 편집해도 원본 스냅샷이 바뀌지 않는지 확인합니다.
- 초기화 후 서버 기준 원본으로 돌아가는지 확인합니다.
- 처음 여는 계약에 이전 계약의 요율 상태가 남지 않는지 확인합니다.

위 항목은 검증 관점을 정리한 것이며, 운영 시스템 전체의 통합 테스트 통과 결과를 의미하지 않습니다.

## 구현 범위

복원 대상은 **실행 중인 앱 안에서의 화면 전환**입니다. `sidebarStore`는 메뉴의 접힘·펼침 상태만 localStorage에 저장하며 업무 스냅샷은 새로고침 후 복원 대상에 포함하지 않습니다.

사용자가 인식하는 업무 단위를 먼저 정하면 어떤 상태를 함께 저장해야 하는지, 언제 복원을 마쳐야 하는지가 분명해집니다. 이 화면에서는 계약 번호가 그 경계였습니다.
