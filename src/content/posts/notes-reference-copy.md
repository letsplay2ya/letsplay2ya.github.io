참고 계약을 보면서 상품과 기간 일부만 가져오고 싶다. 전체 객체를 덮으면 현재 계약의 다른 값까지 바뀌고, 화면에 보이는 이름만 바꾸면 서버에 보낼 코드는 이전 값을 가리킬 수 있다. 복사는 단순 문자열 대입보다 어떤 값들을 함께 이동할지 정하는 작업에 가깝다.

## 원본 코드는 선택한 필드를 어떻게 적용하나

코리안리의 `DefaultContract/index.tsx`는 선택 데이터를 필드 식별자와 code·value로 받아 분기한다. 상품코드를 적용하는 부분에서는 코드와 상품명을 함께 설정한다. 다음은 확인한 분기를 발췌한 것이다.

```ts
case 'gdCd':
  setGdCd(code);
  setGdNm(value);
  break;
```

모든 필드를 동일하게 복제하지 않는다. 계약자나 주소처럼 코드·여러 표시값을 나누는 분기도 있고 목록형 데이터도 있다. 이 사실은 복사 대상을 업무 필드에 맞게 해석해야 한다는 근거다. 백엔드 트랜잭션의 원자성을 보장한다는 뜻은 아니다.

## 화면을 통해 확인하기

[프로젝트의 선택 복사 화면](/projects/koreanre-ai-assistant/#workspace-title)에는 상품·기간·지역 세 묶음만 남겼다. 실제 고객 데이터 대신 두 계약과 참고 계약을 만들었다.

1. 계약 A의 검토 메모를 수정한다.
2. 참고 계약의 상품 항목만 선택해 복사한다.
3. 코드와 이름이 함께 바뀌고 기간·지역·메모는 유지되는지 확인한다.
4. B로 갔다가 A로 돌아와 편집값을 확인한다.

원본 React의 `AiSummaryBox`, `KeywordHighlightText`, `ReferenceCopyButton`을 가져와 이미지·공통 UI 의존성만 작은 어댑터로 바꿨다. 전체 앱을 실행한 것은 아니다. 원본의 전체 store·API·인증 연결을 옮기는 대신 설명할 경계를 좁혔다.

## 원본과 예제의 경계를 표시하기

실제 원본은 필드별 setter와 여러 Zustand store, 업무 스냅샷으로 동작한다. 예제는 소규모 계약 상태를 React 안에 보관한다. 변경 확인창과 마지막 복사 되돌리기는 과정을 관찰하기 위해 새로 추가한 기능이다. 이를 원본에서 구현한 기능처럼 설명하지 않는다.

페이지를 새로고침하면 예제 편집은 초기화된다. 원본의 작업 스냅샷 역시 새로고침 뒤의 서버 저장과 같은 개념이 아니다.

## 복사한 객체를 그대로 공유하지 않기

참고 계약의 중첩 객체를 현재 계약과 공유하면 이후 편집이 참고 데이터까지 바꿀 수 있다. 예제의 적용 함수는 선택한 값을 복제해 반영한다. 선택하지 않은 값은 현재 계약을 유지하고, 확인창을 연 계약과 적용 대상이 다르면 종료한다.

검증에서는 코드·이름 동시 반영, 미선택 항목 보존, 원본 참고 객체 불변, 대상 계약 변경, 빈 선택을 나눠 확인한다. 화면에서는 선택 없음 버튼 비활성화, 확인창 취소, A→B→A 복원을 확인한다. 이 예제 테스트와 실제 운영 환경의 전체 통합 검증은 구분한다.

근거: 원본의 `DefaultContract/index.tsx`, `ContractReference.tsx`, `reference-copy/ReferenceCopyButton.tsx`, `useUwSnapshot.ts`. [계약별 상태 복원 글](/writing/notes-workspace-state/)에서 스냅샷 범위를 이어서 설명한다.
