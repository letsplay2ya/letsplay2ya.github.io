DocuON의 문서 등록 화면에서는 성공을 알리는 창이 두 번 뜬다. 먼저 공동인증서 확인이 끝났다는 안내가 나오고, 잠시 뒤 문서가 등록됐다는 안내가 나온다. 두 창 사이에 실제 첨부파일을 보내는 요청이 있다. 사용자가 첫 번째 창만 봤다고 할 때 프론트엔드에서 어디까지 진행됐다고 말할 수 있을까?

## 파일 두 개를 붙이고 하나를 빼 보면

가상의 문서 ‘11월 점검 기록’을 등록해 보자. 보존 기간은 1년 6개월이고, 첨부는 `점검표.pdf`와 `안내문.txt` 두 개다. 브라우저에서 파일을 고르면 PC에서는 종류·파일명·크기가 표에 나오고 모바일에서는 카드가 생긴다. 여기까지는 브라우저 안에서 일어나는 일이다.

첨부를 받을 때 화면은 두 가지를 보관한다. 하나는 표와 카드에 쓸 표시 정보이고, 다른 하나는 브라우저가 건넨 `File` 객체다. 표시 크기는 바이트 수를 1024로 두 번 나눈 뒤 소수점 둘째 자리까지 표현한다. 이 값만으로는 파일을 전송할 수 없으므로 실제 객체가 별도로 필요하다. 선택이 끝나면 파일 입력값을 비워 같은 파일을 다시 고를 수 있게 한다.

이제 두 번째 첨부를 지워 보자. 삭제 함수는 전달받은 인덱스로 표시 목록과 실제 파일 목록 양쪽에서 각각 한 건을 지운다. 이 예시가 제대로 동작했는지는 표에서 행 하나가 사라진 것만 봐서는 알 수 없다. 이후 서명에 사용할 파일명과 등록 요청에 담길 실제 파일까지 모두 `점검표.pdf` 한 개여야 한다. 첨부 삭제를 테스트한다면 이 세 곳을 함께 보겠다.

## 서명에 넘기는 값과 등록 요청에 담는 값

‘문서 등록’을 누르면 보존 기간, 한 개 이상의 첨부, 제목, 키워드를 검사한다. 보존 기간은 연도와 개월이 모두 0이면 진행할 수 없다. 예시의 1년 6개월은 `1 × 12 + 6 = 18`개월로 바뀐다. 입력 검사를 통과하고 외부 서명 모듈을 사용할 수 있어야 전자서명이 시작된다.

| 시점 | 화면에서 다루는 값 | 예시에서 남는 것 |
| --- | --- | --- |
| 첨부 목록 표시 | 파일명·종류·표시 크기 | 점검표 한 줄 |
| 전자서명 요청 | 문서 분류, 보존 기간, 제목 등 문서 정보와 첨부파일 이름으로 만든 문자열 | 18개월, 점검 기록 제목, `점검표.pdf`라는 이름 |
| 등록 요청 | 문서 정보와 서명 결과를 넣은 JSON, 선택한 파일의 실제 데이터 | JSON 한 부분과 PDF 파일 한 부분 |
| 등록 성공 확인 후 | 등록 응답이 돌려준 증명서 정보 | 상세 창에 표시할 자료 |

전자서명 단계에서 파일과 관련해 문자열에 들어가는 값은 **파일 이름**이다. 실제 첨부 데이터가 어디로 가는지 확인하려면 등록 함수를 봐야 한다. 이 함수가 JSON을 `Blob`으로 만들고, 남아 있는 `File`을 각각 같은 이름의 파일 필드에 추가한 뒤 `FormData`를 한 번 전송한다. 처음 선택한 두 개 중 하나를 지웠으므로 이 예시의 파일 필드는 한 개다.

## 첫 번째 안내를 닫아야 저장 요청이 시작된다

외부 서명 모듈이 결과를 돌려주면 콜백이 성공 여부를 확인한다. 실패 응답이면 오류 처리 후 여기서 돌아간다. 성공하면 서명 결과를 보관하고 인증 확인 안내를 띄운다. **콜백이 도착한 시점과 등록 함수를 호출하는 시점 사이에 사용자의 확인이 한 번 더 있다.**

두 번째 안내는 등록 요청의 응답이 화면의 성공 조건을 만족했을 때 나온다. 사용자가 이를 확인하면 해당 응답에 담긴 증명서 정보로 상세 창을 연다. 열린 상세 창을 닫으면 문서 목록으로 이동한다. 따라서 증명서를 아직 열지 않은 사용자도 이미 등록 성공 응답을 받았을 수 있다. 반대로 첫 번째 안내까지 봤다는 사실만으로는 등록 성공 응답의 도착 여부를 알 수 없다.

이 차이는 ‘마지막으로 무엇을 보셨나요?’라는 질문을 구체적으로 바꿔 준다. 첨부를 전부 지워서 진행이 멈췄다면 입력 검사를 살펴볼 차례다. 서명 안내까지 확인했다면 다음 관찰 대상은 등록 요청과 그 응답이다. 문서 등록 안내까지 봤는데 증명서를 볼 수 없었다면 응답에 담긴 증명서 정보와 상세 창을 여는 조건을 살펴보게 된다. 실제 저장 결과를 확인하기 전에는 화면 상태만 보고 재등록이 필요한지 단정하기 어렵다.

흐름을 확인한 파일은 `DocRegistration.vue`다. 첨부 선택·삭제는 `handleFileChange`와 `deleteFileByIndex`, 서명 입력은 `registerCertificate`와 `buildSignString`, 확인 이후의 전송은 `signCompleteCallback`과 `postDocument`에서 이어진다. 포털과 관리자 화면이 각각 맡는 일은 [DocuON 프로젝트 기록](/projects/docuon/)에 정리했다.
