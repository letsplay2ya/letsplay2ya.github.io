## 같은 문서를 보는 두 사람

DocuON은 전자문서를 등록하고 보관하며 증명서 발급과 이관을 다루는 서비스입니다. 저는 이 프로젝트에서 Vue 프론트엔드 개발에 참여했습니다. 포털에서는 문서를 맡긴 사람이 “내 문서가 어떻게 됐나”를 확인하고, 관리자 화면에서는 운영자가 “이 신청을 처리해도 되나”를 판단합니다. 관리자 Java 코드까지 함께 읽으면 각 화면의 ‘완료’가 어느 일을 가리키는지 알 수 있습니다.

| 구성 | 사용자의 행동 | 코드에서 따라간 지점 |
| --- | --- | --- |
| 사용자 포털 · Vue 3, Vuetify | 파일 첨부, 문서 등록, 보관 문서의 이관 신청 | 첨부 목록과 실제 파일을 함께 갱신하고, 서명 결과를 받은 뒤 등록 요청을 구성합니다. 이관 신청은 문서 상세에서 시작합니다. |
| 관리자 화면 · Vue 3, Pinia | 신청 목록에서 한 건을 열고 승인 또는 반려 | 신청 ID로 상단의 처리 정보와 하단의 대상 문서 목록을 각각 조회합니다. 결정이 저장되면 두 영역을 다시 읽습니다. |
| 관리자 백엔드 · Java 17, Spring Boot, MyBatis | 신청 접수 및 심사 결과 기록 | 신청과 파일별 상세 이력을 연결합니다. 반려할 때는 연결된 문서를 찾아 서비스 상태도 복구합니다. |

## 첨부파일 두 개를 등록하면

점검표와 별지를 골랐을 때 사용자가 먼저 보는 것은 파일명과 크기입니다. 이 단계에서 별지를 지우면 화면에서 한 줄이 사라집니다. 실제 등록에서 더 중요한 변화는 전송할 파일도 하나 줄었다는 점입니다. 포털은 표에 표시할 정보와 전송에 쓸 파일 객체를 따로 보관하고, 삭제할 때 두 목록에서 같은 위치를 지웁니다.

등록 버튼 이후에도 확인할 시점이 두 번 있습니다. 전자서명 결과를 받고 사용자가 확인하면 문서 정보와 실제 파일을 전송합니다. 등록 성공 응답을 받아야 증명서 상세를 열 수 있습니다. 첨부 두 개 중 하나를 빼는 예로 그 차이를 따라갔습니다. [전자서명이 끝난 문서는 언제 등록된 걸까](/writing/docuon-registration/)

## 이관 신청 한 건에 남는 기록

사용자는 문서를 선택하지만 운영자가 여는 것은 **신청 한 건**입니다. 본문과 별지가 딸린 문서를 이관하면 서버는 신청을 한 건 만들고 첨부 두 개를 각각 그 신청에 연결합니다. 운영자는 신청 사유와 대상 문서의 파일 수를 확인하고 한 번 심사합니다.

위 예제에서 같은 문서를 한 번은 승인하고, 처음부터 다시 시작해 한 번은 반려해 보세요. 승인 직후에는 신청 상태만 달라집니다. 반려하면 신청에는 처리 사유가 남고 문서는 다시 이용할 수 있습니다. 두 결과가 갈리는 지점은 관리자 서비스에서 확인한 동작을 따랐습니다. [문서 이관을 승인하면 파일도 옮겨진 걸까](/writing/docuon-transfer-review/)

예제는 포털의 신청 양식과 관리자의 상세·사유 입력 화면을 한 페이지에 재구성했습니다. 문서와 보관소는 가상 데이터이며, 두 상태를 나란히 보는 처리 현황과 처음부터 다시 보기 기능을 더했습니다. 모든 조작은 현재 브라우저 화면 안에서 끝납니다.
