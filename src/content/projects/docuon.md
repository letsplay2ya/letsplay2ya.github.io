## 문서 한 건에 원본 파일이 두 개라면

한 회사의 담당자가 ‘11월 장비 점검 기록’을 등록합니다. 본문은 PDF 한 개이고 현장 사진 한 장이 붙습니다. 담당자가 정하는 제목과 보존기간은 하나지만, 나중에 둘 중 어느 파일을 열람하고 어떤 기록에 대해 증명서를 받을지는 따로 선택할 수 있어야 합니다. 이 문서 한 건을 사용자 포털, Java 서비스, 관리자 화면에서 차례로 따라가 보겠습니다.

포털에서 보존기간을 1년 6개월로 선택하고 전자서명을 마치면, 문서 정보와 서명 결과, 실제 파일 두 개가 한 요청에 담깁니다. 서비스는 첨부를 임시 저장하고 등록 시각에 18개월을 더해 만료 예정일을 정한 뒤 보관을 요청합니다. 보관 시스템이 성공을 반환해야 보관 묶음의 식별자와 최초 증명서 정보를 받습니다. 이때 다운로드 목록에 나오는 것은 **최초 증명서**입니다. 보관한 PDF와 사진은 이후 문서 상세에서 발급받을 수 있습니다.

<div aria-hidden="true"><span id="포털에서는-11번째-첨부를-지워-봤다"></span></div>

등록 화면을 점검할 때도 파일 개수만으로는 부족했습니다. 표가 한 페이지에 열 개씩 보일 때 둘째 페이지 첫 줄의 화면 순번은 0이고 전체 파일 목록의 위치는 10입니다. 원본 Vue 구성요소에 가상 파일 11개를 넣어 그 줄을 삭제하자 1번 파일이 빠지고 11번은 전송 대상에 남았습니다. 화면 목록과 전송 목록은 모두 열 개라서 개수만 비교하면 이 문제를 놓칩니다. [삭제 후 실제로 남는 첨부 비교하기](/writing/docuon-registration/#attachment-review)

## 열람과 발급은 돌려주는 결과물이 다릅니다

문서 상세 요청을 받으면 서비스는 먼저 문서 기본 기록, 이어서 첨부 상세 기록의 무결성을 검사합니다. 검사에 실패하면 포털이 경고를 표시하고 정상 상세 화면을 여는 절차를 멈춥니다. 이용 가능한 문서를 열면 해당 사용자에게 허용된 작업을 선택할 수 있습니다.

| 담당자의 목적 | 무엇을 선택하는가 | 돌려받는 결과 |
| --- | --- | --- |
| 사진 한 장 열람 | 열람 가능 목록에서 사진 선택 | 선택한 파일을 받아 이미지 뷰어에 표시. PDF를 고르면 PDF 뷰어에 표시 |
| 보관한 문서 발급 | 문서 단위로 원본 발급 요청 | 원본이 하나면 파일 그대로, PDF와 사진이 모두 반환되면 ZIP 한 개. 동봉된 증명서는 별도 다운로드 |
| 처리 사실 증명 | 증적 이력에서 특정 처리 한 건 선택 | 증적 번호와 처리 유형에 맞는 정책으로 발급한 증명서 정보와, 제공된 경우 증명서 파일 |

여기서 **증적**은 등록·발급처럼 어떤 처리가 이루어졌는지 남긴 기록입니다. 사용자가 증적 한 건을 골라 증명서를 신청할 때는 처리 유형에 맞는 발급 정책이 필요합니다. 이미 발급된 증명서를 다시 확인할 때는 증명서 ID로 발급 이력을 엽니다. 똑같은 점검 기록을 열고 있어도 ‘사진을 보여 달라’, ‘원본과 증명서를 달라’, ‘이 처리가 이루어졌음을 증명해 달라’는 요청은 선택 대상부터 다릅니다.

## 보존기간을 늘리거나 폐기를 결정하는 시점

점검 기록을 6개월 더 보관하기로 하면 포털은 문서 ID와 추가할 6개월을 보냅니다. Java 서비스는 이를 보관 시스템이 받는 연·월 형식으로 바꾸고, 응답의 성공 여부와 본문에 담긴 처리 결과까지 확인합니다. 포털은 성공 후 상세를 다시 조회해 보관 시스템에 반영된 만료일을 보여줍니다.

단건 폐기 화면에는 **폐기 전에 원본을 발급받을지** 선택하는 항목이 있습니다. 담당자가 서명해 신청하면 서비스는 기존 폐기 신청을 확인하고 대기 이력을 남깁니다. 원본을 받기로 했다면 문서 발급부터 수행합니다. 발급에 실패하면 이력에 실패를 기록하고 폐기 호출 전 멈춥니다. 폐기를 요청한 경우에도 보관 시스템 응답 본문에서 성공을 확인한 뒤에야 이력을 완료로 바꿉니다.

CSV로 여러 문서의 폐기를 신청하는 경우 업로드 직후 확인할 수 있는 것은 **대기 목록 등록**까지입니다. 파일에 이미 신청된 문서가 있으면 서비스는 새 대기 건을 하나도 등록하지 않고 중복 오류를 반환합니다. 접수한 건은 스케줄러가 활성화됐을 때 별도로 처리하고, 운영자는 관리자 화면에서 대기·성공·실패 상태를 문서별로 조회합니다.

## 문서 이관을 심사할 때 운영자가 확정하는 것

사용자가 다른 보관소로 옮기려는 대상은 문서 한 건입니다. 포털에서 목적 보관소와 사유를 보내면 서비스는 신청 한 건을 만들고, 그 신청에 문서의 첨부를 각각 연결한 뒤 문서를 ‘이관 처리 중’으로 바꿉니다. 이 세 작업은 한 트랜잭션 안에서 처리됩니다. 관리자는 신청 상세 상단에서 신청 사유와 처리 상태를 읽고 하단에서 대상 목록을 확인합니다. 본문과 사진가 각기 다른 이력 순번을 받아 같은 문서 제목이 두 줄로 나타나도 **심사할 신청은 하나**입니다. [첨부별 조회와 문서별 합계 비교](#transfer-rows)

<div aria-hidden="true"><span id="승인-다음에-다시-조회하는-이유"></span></div>

접수 상태에서 운영자가 처리 사유를 적고 승인을 확정하면 신청 이력에 승인 결과와 사유가 기록됩니다. 이 승인 요청으로 확인되는 시점은 운영자가 이관을 허가한 때까지입니다. 파일이 상대 보관소에 도착했다는 판단에는 별도의 완료 근거가 필요합니다. 반려할 때는 신청 이력에 사유를 남기는 데 더해, 그 신청에 연결된 문서를 찾아 서비스 상태를 다시 활성으로 바꿉니다. 그 덕분에 사용자는 반려 사유를 확인하면서 원래 문서를 다시 이용할 수 있습니다. 관리자 화면은 심사 요청이 성공하면 신청 정보와 대상 목록을 다시 읽습니다. ## 같은 문서에서 등록은 한 건, 증명서 발급은 두 건이 되는 이유

포털의 월별 문서 등록 현황은 해당 월에 새로 등록한 문서를 셉니다. 가령 11월 7일에 본문 PDF 1 MiB와 사진 256 KiB를 한 문서로 등록하고 그달에 다른 등록이 없었다고 하겠습니다. 월 등록은 **1건**이고, 용량 집계에는 두 파일을 더한 **1,310,720바이트**가 들어갑니다. 일별 그래프에는 7일에 한 건이 찍히고 나머지 날짜에는 0건이 채워집니다. 일평균은 문서를 올린 날만 골라 계산하지 않고 11월의 30일로 나누므로 **0.03건**입니다. 문서가 12월에도 보관돼 있다는 이유로 12월 신규 등록량에 다시 더해지지는 않습니다.

관리자가 ‘증명서 발급 통계’를 열면 질문이 달라집니다. 선택한 이용자가 **조회 기간에 발급받은 증명서**를 유형별로 세며, 최초 등록용 유형과 폐기된 증명서는 집계에서 빠집니다. 같은 문서에 최초 등록용 증명서 한 건이 있고, 기간 안에 일반 증명서를 세 번 발급받아 그중 한 건을 폐기했다면 발급 합계는 **2건**입니다. 등록 화면의 첨부 수, 보관 중인 문서 수, 발급 이력 전체를 세어서는 이 숫자를 설명할 수 없습니다.

포털·관리자 Vue 화면과 Java 서비스·집계 SQL을 기준으로 설명했습니다. 점검 기록의 파일명과 수량·용량은 동작을 설명하기 위한 예시입니다. 이관 대상의 조회 단위와 심사 결과는 가상 자료로 재현한 화면에서 확인할 수 있습니다. [이관 조회와 심사 구현 읽기](/writing/docuon-transfer-review/)
