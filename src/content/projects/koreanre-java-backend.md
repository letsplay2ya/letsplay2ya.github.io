코리안리 시스템의 Java 백엔드 소스를 분석한 초안입니다. 같은 시스템의 [프론트엔드 사례](/projects/koreanre-ai-assistant/)와 연결됩니다. 별개의 수행 프로젝트로 집계하지 않으며, 아래 구조를 개인 개발 성과로 주장하지 않습니다. 담당 범위가 확인되면 역할과 구현 경험을 보강해 공개합니다.

## 시스템 구성

Java 17과 Spring Boot를 기반으로 HTTP API와 서비스 계층을 구성하고, MyBatis로 PostgreSQL에 접근합니다. Maven 의존성에서 검증·보안·API 문서화와 S3 파일 연동 구성을 확인했습니다. 의존성의 존재와 직접 개발 여부는 구분합니다.

## 통합 저장 — 여러 탭을 하나의 계약 상태로

화면은 기본정보, 담보 구조, 약관을 나누어 편집하지만 저장 시에는 서로 연결된 계약 상태로 취급해야 합니다. `IntegratedSaveService.save`는 다음 순서로 동작합니다.

```text
요청 검증 → 계약 잠금 · 서버 업무상태 검사
  → 기본정보 / 상품별 담보 / 약관 변환
  → 약관 일련번호 계획 → 기존 최신본 아카이빙
  → 새 최신본 삽입 → 저장 결과 재조회
```

`@Transactional` 서비스 메서드 안에서 실행하며, 잠금 시점의 서버 업무상태를 새 데이터에 보존합니다. 브라우저가 보낸 값으로 서버 상태가 덮이지 않도록 하는 지점입니다. 운영 환경의 동시성·성능을 측정한 결과는 포함하지 않습니다.

## 상품별 전략 — 공통 순서와 개별 구조 분리

`CoverageDetailSaveUnitResolver`는 주입받은 `CoverageDetailSaveUnit` 목록에서 요청 상품을 지원하는 구현을 선택합니다. 공통 서비스는 저장 순서를 관리하고, 상품별 구현은 담보 데이터 검증·변환·Writer·재조회를 제공합니다. 지원하지 않는 상품은 예외로 종료합니다.

## Full Snapshot — 최신본과 변경 이력

현재 설계 문서는 기본 모드를 `GLOBAL_FULL_SNAPSHOT`으로 정의합니다. 기존 최신본을 먼저 이력으로 옮긴 뒤 요청 데이터로 최신 상태를 재생성합니다. 일부 필드만 바꾸는 PATCH와 달리 빠진 항목의 삭제 의미도 고려해야 합니다.

상품별 설정에 따라 복구용 `LEGACY_HYBRID` 경로를 선택할 수 있습니다. 소스와 설계 문서를 확인한 설명이며 실제 운영 설정을 확인했다는 의미는 아닙니다.

## 검증할 경계

- 상위·하위 데이터의 계약 식별자 일치
- 같은 계약에 대한 동시 저장과 상태 보존
- 담보 관계와 약관 일련번호 정합성
- 빈 목록과 누락된 목적물의 삭제 의미
- 아카이빙 후 삽입 실패 시 트랜잭션 롤백

저장 모델·통합 저장·아키텍처 하네스 테스트 파일의 존재를 확인했습니다. 이번 작업에서 백엔드 테스트와 운영 DB 저장을 실행하지 않았으므로 테스트 통과나 운영 안정성을 검증했다고 표기하지 않습니다.

## 개인 기여 작성 대기

실제 담당 API, 상품군, 공통 저장 처리 여부와 해결한 문제를 확인한 뒤 보강합니다. 현재 사이트 미게시 초안으로 프로젝트 목록과 정적 배포 경로에서 제외합니다. 소스 저장소에는 분석 원고가 포함됩니다.
